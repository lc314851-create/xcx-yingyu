# 同行「自定义词书」功能调研

> 调研时间：2026-09-22
> 目的：为「用户上传生成个人词书」功能确定做法与边界
> 可信度标注：🟢 官方文档/官方帮助页 · 🟡 多个二手来源一致 · ⚠️ 单一来源，待核实

---

## 一、一句话结论

**没有一家主流背单词产品做「上传一段英文 → 自动抽词 → 生成词书」这件事。**

它们全部走的是「**让用户提供单词列表**」——最多帮你把纸质单词表 OCR 成文字，或把粘贴的文本切分成词条。**"从文本里找出有哪些单词"这一步，是它们集体空出来的位置。**

这对你意味着两件事：
1. 你的想法比同行更轻（用户不用自己整理词表），是真实的差异化空间；
2. 但也意味着**词形归一、功能词过滤、释义匹配这三件事没有现成参照**，得自己想清楚——这正是前面实测暴露出来的那部分工作量。

---

## 二、逐家做法

### 墨墨背单词 🟡

| 项 | 做法 |
|---|---|
| 入口 | ① 应用内「词库管理 → 自定义词书 → 添加词书」<br>② 文件上传：支持 TXT / CSV / TSV / XLS / XLSX<br>③ 粘贴纯文本，点「解析」 |
| 格式要求 | 文件：每行一个词条，或「单词,释义」逗号分隔。粘贴：每行一个单词 |
| 释义来源 | **系统自动匹配内置词典库**；匹配不到的，**提示用户手动补充音标和中文释义** |
| 匹配辅助 | 匹配度低的会列出近似选项让用户确认 |
| 去重 | 自动去重，与内置词库重复的不重复计学习量 |
| 失败处理 | **保留「导入记录」错误日志**，方便用户修正原文件后重新上传 |
| 可见性 | 自定义词书在「我的词库」中私有；另有公开词库商城供搜索订阅 |
| 商业模型 | **单词上限制**：新用户 600 词免费，扩容付费 8~163 元（550~17600 词），也可通过签到/分享/邀请/投稿免费增加 |

> 值得注意：墨墨把「自定义词库」直接接进了它的付费模型——词库越大越要扩容。这是它的核心变现点。

### 百词斩 🟡

| 项 | 做法 |
|---|---|
| 入口 | 底部「单词本」→ 右上角「+」→「创建单词书」 |
| 五种添加方式 | ① 手动逐条输入 ② **拍照 OCR 识别** ③ TXT / CSV 文件导入 ④ 从「我的收藏」导出（单次最多 20 个）⑤ 扫描实体书二维码绑定官方词库 |
| 命名限制 | 词书名称**最多 10 字**，可选分类与封面 |
| OCR 细节 | 拍照后自动识别，识别结果**逐条勾选**导入，需人工校对（要求单词间逗号分隔、区分大小写） |
| 释义来源 | 自填为主；OCR 只提取原文文字 |

### 扇贝单词 🟡

| 项 | 做法 |
|---|---|
| 入口 | **仅网页端**（shanbay.com → 工具箱 → 自建词书），App 内下拉同步 |
| 格式 | TXT：**每行「英文+中文释义紧挨着，中间不加任何空格或标点」**（如 `abandon放弃`）；或 CSV（UTF-8，首列英文、次列中文，禁用逗号引号） |
| 释义来源 | **用户自己在文件里提供**，系统不做自动匹配 |
| 容错 | 解析异常行高亮提示，可「跳过错误行」继续 |
| 可见性 | **保存时可勾选是否「公开」**，公开即进社区词库 |
| 命名 | 可填名称 + 简介 |

> 扇贝的格式约束是这批里最苛刻的（连空格都不许有），说明它走的是"零歧义解析"路线，把复杂度全推给用户。

### 不背单词 🟡

| 项 | 做法 |
|---|---|
| 入口 | **仅网页端**（右上角菜单 →「自定义词书」→ 上传文件），保存后同步到 App |
| 格式 | TXT（UTF-8），**每行仅一个英文单词，不含释义** |
| 释义来源 | 系统匹配 |
| 容错 | 格式异常或拼写存疑的单词**标红提示**，用户可手动编辑 |
| 可见性 | 进入「单词本 → 上传」分类，私有 |

> 不背单词是这批里最接近你设想的：**用户只给单词，释义由系统补**。但它仍然要求用户自己先整理出一张干净的单词列表。

### 欧路词典 🟢（官方帮助页）

| 项 | 做法 |
|---|---|
| 入口 | 生词本 → 右上角「三点」→「导入单词」 |
| 方式 | ① **文本导入** ② **拍照导入**（拍摄含生词的纸质材料提取） |
| 其他 | 生词本支持分组、按添加时间/字母/单词等级排序；生词本与笔记、学习记录**多端云同步** |
| 词库体系 | 完全开放的第三方词库（MDict / 灵格斯 / Babylon mdx+mdd），另有官方词库编辑器 |

> 欧路是"词典优先"路线：它不叫词书，叫**生词本**——用户查词顺手收藏，而不是刻意导入。

### Anki 🟢（官方文档）

| 项 | 做法 |
|---|---|
| 入口 | **桌面端** File → Import（移动端只能导入 apkg，导入能力弱） |
| 格式 | 纯文本 TXT / CSV / TSV，**必须 UTF-8**；分隔符逗号/分号/制表符自动猜测，可手动改 |
| 关键机制 | **字段映射**：把文件里的列映射到卡片的正/反面/标签字段；支持忽略首行表头 |
| 头部配置 | 2.1.54+ 支持文件内嵌配置头（分隔符、笔记类型、目标牌组、标签）自动填好 |
| 释义来源 | 用户自填（Anki 只是记忆引擎，不含词典） |
| 同步 | AnkiWeb 账号多端双向同步（牌组 + 复习记录）；不登录也能纯本地离线用 |

### Quizlet 🟢（官方帮助页）

| 项 | 做法 |
|---|---|
| 入口 | ① 网页端 Paste text（粘贴，自动识别词/释义）② 上传 .pdf / .docx / .pptx ③ **Scan document 扫描文档** ④ 手动逐条 |
| 扫描细节 | 拍照/选图 → 自动框选识别到的文字 → **用户手指划选哪些是"词"、哪些是"释义"** → 逐条加入；单次扫描要求**至少 100 字符** |
| 门槛 | **扫描文档仅 Quizlet Plus 付费订阅及教师版可用**（iOS/Android）；未达法定年龄也不可用 |
| 可见性 | **新建卡片集默认公开**，可改为「有密码的人可见」或「仅自己」 |
| 发布限制 | **至少 2 张卡片才能发布** |
| 增长逻辑 | 默认公开 + 搜索已有卡片集，靠社区内容做增长 |

## 三、归纳：四种流派

| 流派 | 代表 | 形态 |
|------|------|------|
| **文件流** | Anki、扇贝、不背单词、墨墨 | 电脑端准备文件 → 上传 → 字段/格式解析。格式要求普遍严格 |
| **粘贴流** | 墨墨、百词斩、Quizlet | 应用内粘贴文本，系统自动切分。最轻，无需外部工具 |
| **OCR 流** | 百词斩、欧路、Quizlet | 拍纸质单词表 → OCR → 人工校对。**全部在企业主体或付费墙后** |
| **沉淀流** | 欧路、百词斩、不背单词 | 不刻意导入，从"查词/阅读/收藏"中自动沉淀成生词本 |

关键观察：**"文件流"和"粘贴流"的共同前提是——用户手上已经有一张单词表。** 你的场景不是。

## 四、六条可借鉴 / 要避开

### ✅ 值得抄的四条

1. **未匹配的词，让用户补释义而不是直接丢弃**
   墨墨、Quizlet 都是这么做的：匹配不到 → 提示手动填音标和释义。你原方案是"丢弃但告知"，可以升级成"**丢弃 or 手动补全（二选一）**"。专业术语、人名、自造词正是用户最想自己掌控的部分。

2. **保留解析失败记录，允许修正重传**
   墨墨的「导入记录」把失败行留档。实现成本很低（存一份 `failedLines` 字段），但体验差距很大。

3. **上限定在"提示"而不是"拦截"**
   同行的限制（百词斩名称 10 字、Quizlet 至少 2 张卡）都是**软性提示**，不是硬报错。你的"500 词 / 20 本"上限也应按这个调性做文案。

4. **词书名称之外，留一个简介字段**
   扇贝支持名称 + 简介。用户场景是"我那篇经济学人"，简介可以放来源/日期，成本几乎为零。

### ⚠️ 必须避开的三个坑

1. **别学扇贝的格式要求**
   它要求"英文和中文紧挨着、不能有任何空格或标点"，把复杂度全推给用户。你是"粘贴一段文字"的场景，**宽容解析**才是你的优势，不要退化成格式校验器。

2. **别默认公开**
   扇贝可选公开、Quizlet 默认公开——它们靠社区词库做增长。你的定位是"只能自己看见"，这是差异点。但要清醒：**你主动放弃了"用户共建词库"这个增长杠杆**，所以第一版别在设计上留"公开"的口子，等真有需求再加。

3. **别把 OCR 当成 MVP 的入口**
   见下节。

### 🔍 关于 OCR 的结论（修正并加强）

我上一轮说"图片建议砍掉"，同行调研后**结论不变，但理由更硬了**：

- **Quizlet 的扫描文档是明确写在 Plus 付费订阅里的功能** 🟢 —— 大厂也把它当作增值项，不做免费默认
- 百词斩、欧路都是**企业主体**，有资金和资质
- 微信服务市场确实有官方「微信OCR识别」服务，资费里含 **「100 次/天，连续发放」的免费档** 🟡 —— 免费额度是有的
- **但**：购买服务市场服务通常要求小程序完成微信认证，而**个人主体不支持微信认证** 🟡；另有开发者在微信开放社区反馈，涉及大模型 OCR 被判定为「深度合成技术，属个人主体尚未开放服务类目」而驳回审核 🟢

> ⚠️ 这一条建议你**亲自去小程序后台「服务市场」点一次**确认可购性——政策会变，这是唯一能确证的方式。如果侥幸能开，100 次/天的免费额度对个人小体量其实够用。

## 五、对你现有方案的具体修改建议

| 现有设计 | 建议改成 | 理由 |
|---------|---------|------|
| 未命中的词直接丢弃 | **丢弃 + 「手动补释义」入口** | 墨墨、Quizlet 都这么做；这是用户真实需求 |
| 无失败记录 | 存 `failedLines`，结果页可查看 | 抄墨墨的「导入记录」 |
| 词书只有 `name` | 增加可选 `desc` 字段 | 抄扇贝；成本近零 |
| 单本 500 词硬上限 | 超出时明确提示"建议拆成两本" | 学百词斩/Quizlet 的软性限制调性 |
| 无"与已有词书合并" | P2 考虑"追加到已有词书" | 用户会想把两篇文章的词并到一本 |
| 图片入口（已砍） | 保持砍掉，但文案引导「用微信长按图片提取文字」 | 与 Quizlet 把扫描放付费墙后是同一逻辑 |
